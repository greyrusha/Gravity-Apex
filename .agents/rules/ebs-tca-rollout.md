# Oracle EBS R12 TCA Customer OU Rollout Rules

1. **Multi-OU Credit Limits & Profiles Live on `BILL_TO` Site Uses:** In Terex Multi-OU EBS (`HZ_CUSTOMER_PROFILES` / `HZ_CUST_PROFILE_AMTS`), global account-level rows (`SITE_USE_ID IS NULL`) hold global defaults or `0.01` / `1` placeholders, whereas Operating-Unit credit limits, profile classes, collectors, and fallback payment terms (`STANDARD_TERMS`) are stored at the **`BILL_TO` Site-Use level (`SITE_USE_ID = HZ_CUST_SITE_USES_ALL.SITE_USE_ID`)**. Always extract and migrate `SITE_USE_ID`-level credit profiles/amounts for OU rollouts.
2. **Never Collapse `MACHINES` vs. `AFTERMARKET` Accounts:** Customer accounts with distinct `HZ_CUST_ACCOUNTS.ACCOUNT_NAME` streams (`MACHINES` for Capital sales vs. `AFTERMARKET` for Parts & Service) are intentional business splits—even when created under separate `HZ_PARTIES.PARTY_ID` records—and must never be flagged or merged as duplicate customer accounts.

3. **Site & Site-Use Activity-Ranked Deduplication & Single-Pass `@ADG` Aggregation:** In EBS AR/OM (`AR_PAYMENT_SCHEDULES_ALL`, `RA_CUSTOMER_TRX_ALL`, `OE_ORDER_LINES_ALL`), Open AR (`CUSTOMER_SITE_USE_ID`) and billing/shipping transaction counts (`BILL_TO_SITE_USE_ID` / `SHIP_TO_SITE_USE_ID`, `INVOICE_TO_ORG_ID` / `SHIP_TO_ORG_ID`) live on individual Site Uses (`HZ_CUST_SITE_USES_ALL`); always aggregate them in a single `/*+ DRIVING_SITE */` pass by `ORG_ID` (never in N-batch loops over `OE_ORDER_LINES_ALL`) and rank duplicate Site / Site-Use survivors by `Open AR > Activity Count > Primary Flag > Credit Limit`.
4. **EBS `/OA_HTML/RF.jsp?function_id=mLogin` Auth & Internal HTTP ORDS Cookie Guard:** When authenticating APEX users against EBS via outbound HTTPS `mLogin` + immediate `mLogout` (`apex_web_service.make_rest_request`), enforce `^https://` on the outbound EBS origin URL, immediately wipe `apex_web_service` headers/cookies, and omit `secure: true` on the APEX browser session cookie whenever users reach ORDS over an internal `http://` port (e.g. `:7779`), otherwise browsers silently drop the session cookie after login. In APEXlang 26.x Interactive Grids, `whereClause` requires `type: tableView` inside `source`, and Maker-Checker grid locks use `editAuthorization { add / update / delete }`.
5. **APEX Interactive Grid `displayOnly` Lock, DA `fireOnInit: false`, & SQLcl `apex import` Autocommit Trap:** Setting `source { queryOnly: true }` on an Interactive Grid column only excludes it from DML `UPDATE` statements—if `column.type` remains `textField` or `numberField`, double-clicking still opens an inline browser input box; always set `type: displayOnly` on read-only IG columns and `allowedOperations: [ update ]`. In APEXlang 26.x, `dynamicAction` `action` components default `execution.fireOnInit` to `true` (`Yes`) when omitted (which causes `cancelDialog` / `closeDialog` actions to immediately close a modal drawer on load!), so always set `fireOnInit: false` explicitly on click/dialog-close actions. Finally, connect via `sqlcl_run('conn -name APEXQ_AWS')` rather than the MCP `connect` wrapper so JDBC `autoCommit` stays `false` and `apex import` never raises `ORA-17274`.
6. **Verify Dictionary Column Names & Resolve Null `P0_PROJECT_ID` in Authorization Helpers:** Always verify column names (such as `XXCR_EBS_REF_LOVS.ACTIVE_YN`) against `USER_TAB_COLUMNS` and test region SQL directly on `APEXQ_AWS`, because a mid-render `ORA-00904` inside Universal Theme `js-navCollapsed--hidden` pages aborts footer JS initialization and leaves navigation unresponsive. Likewise, APEX authorization helpers receiving `v('P0_PROJECT_ID')` must call `resolve_active_project` when the parameter is `NULL` so post-login page renders never evaluate false negatives before `beforeHeader` processes initialize `P0_PROJECT_ID`.
